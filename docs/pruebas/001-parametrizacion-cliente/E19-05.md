## Historia

Como responsable de la operación, quiero que el plazo que marca un pedido como demorado sea el que
el cliente considera demora, para que el tablero no invente urgencias ni las tape.

## Criterios

### E19-05.1 — Cada canal tiene su plazo confirmado

**Dado** el catálogo de canales, **cuando** se revisa el plazo de cada uno,
**entonces** todos tienen el valor que el cliente confirmó.

- ancla: `apps/api/src/db/seeds/base.ts#CANALES`
- verifica: `manual`

### E19-05.2 — El cálculo de demora usa ese plazo

**Dado** un pedido de un canal cuyo plazo ya venció, **cuando** corre la evaluación periódica,
**entonces** el pedido queda marcado como demorado.

- ancla: `apps/api/src/db/seeds/base.ts#CANALES`
- verifica: `integracion` → `dashboard.itest.ts::demora por SLA de canal`
