## Historia

Como responsable del despliegue, quiero que el dominio del cliente esté configurado en un solo lugar
y que el heredado no pueda sobrevivir en ninguno, para que nadie despliegue una app que rechaza a
todo el equipo o que deja entrar a cualquiera.

## Criterios

### E19-01.1 — Producción no arranca con el dominio heredado

**Dado** un entorno con `NODE_ENV=production`, **cuando** se valida la configuración y el dominio de
Google sigue siendo el placeholder heredado, **entonces** el arranque falla nombrando esa variable.

- ancla: `packages/shared/src/env.ts#apiEnvSchema.GOOGLE_HD`
- verifica: `unit` → `env-schema.test.ts::produccion con el dominio placeholder: rechaza el arranque`

### E19-01.2 — Una cuenta de otro dominio no entra

**Dado** una persona con cuenta de Google fuera del dominio configurado, **cuando** completa el
callback de autorización, **entonces** vuelve al login con el error de dominio y no se crea sesión,
aunque su mail figure en la tabla de usuarios.

- ancla: `apps/api/src/plugins/auth-google.ts#authGoogleRoutes`
- verifica: `integracion` → `auth-google.itest.ts::rechaza una cuenta de otro dominio`

### E19-01.3 — El mensaje de rechazo nombra el dominio real

**Dado** un login rechazado por dominio, **cuando** la pantalla muestra el error,
**entonces** el texto nombra el dominio efectivamente configurado, no uno escrito a mano.

- ancla: `apps/web/src/pages/Login.tsx#GOOGLE_ERROR_MESSAGES`
- verifica: `unit` → `Login.test.tsx::el error de dominio nombra el dominio configurado`

### E19-01.4 — El placeholder no sobrevive en ningún archivo versionado

**Dado** el repositorio, **cuando** se busca el literal heredado fuera de los documentos históricos,
**entonces** no hay ocurrencias.

- ancla: `ninguna` — el alcance es el repositorio entero (16 archivos), no un lugar
- verifica: `estatica` → chequeo en CI
